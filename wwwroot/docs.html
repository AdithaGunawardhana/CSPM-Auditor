Getting Started with Nexus

Nexus is a fully isolated, multi-tenant Cloud Security Posture Management (CSPM) platform. This guide will teach you how to securely link your independent cloud infrastructure, audit it for misconfigurations, and automatically remediate vulnerabilities.

1

Account Authentication

To ensure strict data isolation, every user must authenticate via Google SSO or a secure corporate email. Your identity creates a dedicated tenant sandbox on the Nexus platform.

  • Navigate to the Sign In page.
  • Authenticate using your preferred identity provider.
  • Upon success, your unique Tenant ID is generated to isolate your cloud environments from all other users.

Linking Cloud Accounts to Nexus

Nexus requires cross-account read access to scan your environment, and write access if you wish to use SOAR automated remediation.

AWS Integration Example (IAM Role)

Deploy this CloudFormation template or run the following CLI command in your AWS account to grant Nexus audit access:

aws iam create-role \
  --role-name NexusSecurityAuditRole \
  --assume-role-policy-document '{
    "Version": "2012-10-17",
    "Statement": [{
      "Effect": "Allow",
      "Principal": {"AWS": "arn:aws:iam::NEXUS_ACCOUNT_ID:root"},
      "Action": "sts:AssumeRole",
      "Condition": {"StringEquals": {"sts:ExternalId": "YOUR_TENANT_ID"}}
    }]
  }'

Once created, enter the Role ARN into the Nexus Platform Settings to bind your specific tenant to your cloud environment.

4

Data Isolation Sandbox

The X-Tenant-ID Header System

Nexus is architected as a Multi-Tenant platform. This ensures that while hundreds of users can access the application simultaneously, your data remains completely invisible to everyone else.

Every single request sent to the Nexus Backend is cryptographically tagged with an X-Tenant-ID header matching your verified identity. Entity Framework Core strictly filters all SQLite queries so you can only ever view, scan, or patch resources inside your own dedicated cloud environments. Zero cross-contamination.

5

Navigating the Dashboard

The Security Command Center is your primary view. Because of the Multi-Tenant architecture detailed in Step 4, you will only see data pertaining to the cloud accounts you linked.

KPI Matrix

Monitors the total number of audits run on your infrastructure and tracks active, unresolved threats in real-time.

Risk Distributions

Interactive charts visually breaking down which of your linked cloud providers holds the most risk.

Pre-Flight Scanner

Allows developers to drop local Terraform or Kubernetes manifest files for static vulnerability analysis before deployment.

Live Findings

The main telemetry table detailing exact resources, severity scores, and cryptographic evidence of misconfigurations.

6

Automated Auditing

As an auditor, your goal is to identify risks before they are exploited. You do not need write access to perform audits.

  1. Navigate to the top right of the dashboard.
  2. Click the yellow RUN MULTI-CLOUD SCAN button.
  3. Nexus utilizes read-only APIs to query your infrastructure against CIS Benchmarks.
  4. If a misconfiguration is found (e.g., Port 22 open on Azure, or a Public Bucket on Oracle Cloud), it populates the findings table.
  5. Use the Analyze (AI) button to receive a detailed breakdown of the threat vector.
7

Remediation & SOAR

Role-Based Access Control

By default, all new users are provisioned as VIEWER. To execute active remediation scripts on your cloud infrastructure, you must elevate your privileges.

How to unlock Remediation:

  • 1. Submit Request Navigate to the Profile Dropdown on the dashboard and select Apply for Admin. Submit your justification for SOAR access.
  • 2. Governance Review An authorized Identity Admin must log into the DxO Governance Portal to review your ticket and grant the ADMIN role.
  • 3. Execute Patches Once approved, return to the dashboard. The locked buttons will now transform into active Remediate triggers. Clicking these will fire programmatic API calls to your cloud provider to actively fix the vulnerability.
